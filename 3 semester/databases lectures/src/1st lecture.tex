\section{Типы баз данных}

\begin{itemize}\itemsep0pt
    \item \textbf{Сетевые и иерархические} --- данные организованы в виде иерархии/сети.
    \item \textbf{Реляционные} --- данные представлены в виде таблиц, связанных между собой.
    \item \textbf{Big Data, NoSQL} --- данные хранятся в неструктурированном виде на
    распределённом кластере серверов.
\end{itemize}

\section{История}

\begin{itemize}\itemsep0pt
    \item \textbf{1970} --- реляционная модель данных. Эдгар Кодд разработал реляционную модель данных.
    \item \textbf{1974} --- язык SEQUEL. Реймонд Бойс и Дональд Чамберлин в IBM создали язык запросов
    к реляционной бд SEQUEL (Structured English Query Language).
    \item \textbf{1979} --- выход систем управления бд с поддержкой SEQUEl(sql).
    \item \textbf{1986} --- стандартизация SQL. Последняя версия стандарта --- SQL:2023 (с ревизией от 2026 года).
\end{itemize}

\section{СУБД}

Популярные реляционные СУБД: Oracle Database, Microsoft SQL Server, IBM DB2, MySQL, MariaDB,
PostgreSQL, SQLite.

Популярность СУБД основана на опросе от
(\href{https://survey.stackoverflow.co/2025/technology\#most-popular-technologies-database-database}{опросе от stack overflow в 2025}): PostgreSQL --- 55{,}6\,\%, MySQL --- 40{,}5\,\%, SQLite --- 37{,}5\,\%,
Microsoft SQL Server --- 30{,}1\,\%, Redis --- 28\,\%, MongoDB --- 24\,\%, MariaDB --- 22{,}5\,\%,
Elasticsearch --- 16{,}7\,\%, Oracle --- 10{,}6\,\%.

Еще SQL используют  в нереляционных базах данных: Apache Hive, Apache Spark SQL, Apache Drill.

\subsection{Почему SQL популярен}

\begin{itemize}\itemsep0pt
    \item Строгая математическая основа: реляционная модель данных, реляционная алгебра,
    реляционное исчисление.
    \item Стандарты: ANSI SQL-86 --- SQL:2023.
    \item Большое количество людей знают SQL: многие компании, которые делают системы управления базами данных
    реализуют поддержку SQL для расширения количества пользователей.
\end{itemize}

В джаве и c++ мы привыкли описывать как получить результат, а тут мы описываем какой хотим увидеть результат. В этом и основное отличие sql.

\section{Создание и изменение таблиц}

\begin{lstlisting}
CREATE TABLE superheroes(
    id INT,
    name VARCHAR(100),
    align VARCHAR(30),
    eye VARCHAR(30),
    hair VARCHAR(30),
    gender VARCHAR(30),
    appearances INT,
    year INT,
    universe VARCHAR(10)
)
\end{lstlisting}

\subsection{Типы данных в SQL}

\begin{center}
\begin{tabularx}{\linewidth}{@{}l >{\RaggedRight}X@{}}
    \toprule
    \textbf{Тип данных} & \textbf{Назначение} \\
    \midrule
    \texttt{CHARACTER(n)} (\texttt{CHAR(n)}) & Строка фиксированной длины $n$ \\
    \texttt{CHARACTER VARYING(n)} (\texttt{VARCHAR(n)}) & Строка переменной длины, максимальная длина $n$ \\
    \texttt{BOOLEAN} & Логический тип данных \\
    \texttt{INTEGER} (\texttt{INT}) & Целое число \\
    \texttt{NUMERIC(p,s)} & Действительное число ($p$ --- количество значащих цифр, $s$ --- количество цифр после запятой). Хранится точно \\
    \texttt{REAL} & Действительное число одинарной точности, формат IEEE 754 \\
    \texttt{DOUBLE PRECISION} & Действительное число двойной точности, формат IEEE 754 \\
    \texttt{DATE} & Дата \\
    \texttt{TIMESTAMP} & Дата и время \\
    \bottomrule
\end{tabularx}
\end{center}
Иногда деньги хранятся в виде целого числа, представляющего количество центов, чтобы избежать проблем с точностью. А иногда используют \texttt{DECIMAL} или \texttt{NUMERIC} с фиксированной точностью. Не стоит хранить в даблах или флоатах, так как из за специфики хранения этих чисел, можно в какой то момент получить у пользователь на копейку больше или меньше, чем он должен был получить.
\subsection{Первичный ключ}

\begin{lstlisting}
CREATE TABLE superheroes(
    id INT PRIMARY KEY,
    ...
)
\end{lstlisting}

Заполнение первичного ключа, чтобы он сам проставлялся в таблице при добавлении новых строк:

\begin{lstlisting}
CREATE TABLE superheroes(
    id INT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    ...
)
\end{lstlisting}

\begin{lstlisting}
CREATE TABLE superheroes(
    id SERIAL PRIMARY KEY,
    ...
)
\end{lstlisting}
